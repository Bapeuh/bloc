# Manifeste BLOC

## Tout est Bloc

Un Bloc peut exister seul.

Des Blocs peuvent être reliés.

Les relations font émerger des structures.

Les structures acquièrent du sens lorsqu'elles sont observées et interprétées.

Les structures permettent de construire des outils.

Les outils permettent des usages.

**La complexité doit émerger de la simplicité.**

## Principe fondamental

> **Tout est Bloc.**  
> **Le reste n'est qu'interprétation.**

BLOC ne cherche pas à créer une nouvelle collection d'objets informatiques spécialisés. Il cherche le substrat minimal à partir duquel ces objets peuvent émerger.

Lorsqu'un nouveau concept apparaît :

1. Peut-il être représenté par des Blocs et des relations ?
2. Son type peut-il être une interprétation ?
3. Son comportement peut-il être décrit par des règles ?
4. Sa représentation peut-elle être produite par une lentille et une vue ?

Si oui, ce concept ne doit pas devenir une nouvelle primitive fondamentale.

## Vision

BLOC n'est pas, par nature :

- un système d'exploitation ;
- une base de données ;
- une suite bureautique ;
- un framework ;
- un langage ;
- une interface graphique.

BLOC vise plutôt à être :

> **un substrat universel permettant l'émergence de systèmes numériques.**

Un système d'exploitation, une base de données, un document, un agent, un tableur ou une interface peuvent alors devenir des interprétations et des organisations particulières d'un même univers.

## Le sens n'est pas dans le Bloc

Le sens ne doit pas être confondu avec l'identité.

Un Bloc fondamental ne dit pas ce qu'il est.

Le sens émerge de :

```text
Bloc
  ↓
Relations
  ↓
Contexte d'observation
  ↓
Interprétation
  ↓
Sens
```

Une même réalité BLOC peut donc être comprise de plusieurs manières sans duplication de la réalité sous-jacente.

## Lentilles et vues

Une **lentille** est un ensemble de règles d'interprétation appliquées à un univers de Blocs.

```text
Univers BLOC
    ↓
Lentille
    ↓
Interprétation
```

Une **vue** rend cette interprétation perceptible ou manipulable.

```text
Univers
   ↓
Lentille
   ↓
Interprétation
   ↓
Vue
   ↓
Perception / interaction
```

La lentille comprend.  
La vue rend perceptible.

Une lentille n'est donc pas nécessairement une application.

## L'application réinterprétée

Le modèle classique tend à séparer :

```text
Application + Données
```

BLOC cherche plutôt :

```text
Univers de Blocs
      ↓
   Lentille
      ↓
Interprétation
      ↓
     Vue
```

Une « application » peut alors émerger comme un assemblage de lentilles, de vues, de règles, de capacités et de contextes.

## Le test permanent

À chaque décision architecturale :

> **Est-ce réellement fondamental ?**  
> **Ou est-ce une interprétation ?**

Si c'est une interprétation, ne pas alourdir le cœur.

Utiliser les Blocs, les relations, les règles d'interprétation et les lentilles.

---

**Résumé :**

> Tout est Bloc.  
> Le reste n'est qu'interprétation.  
> Les relations font émerger les structures.  
> Le contexte et les lentilles font émerger le sens.  
> Les vues rendent ce sens perceptible.
